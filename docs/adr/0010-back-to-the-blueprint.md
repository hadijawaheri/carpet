# 0010 · Back to the blueprint

Date: 2026-10-22 · Status: accepted (owner chose "align" for every deviation in the blueprint conformance report)

Supersedes the Redis, migration and Docker points of 0009.

- **No Docker in production.** The Dockerfiles and the compose `app` profile are gone. `infra/docker-compose.yml` is development Mongo only. Production MongoDB 8 is installed natively by `infra/server/setup-mongo.sh` from MongoDB's apt repository, with `infra/mongo/mongod.conf`: 127.0.0.1:27017, single-node replica set `rs0`, auth with a key file, users `root` and `farsh_app`. Backups use the host's `mongodump` (`MONGO_PORT` picks dev 27018 or production 27017).
- **No Redis until its entry condition holds.** The API runs as one PM2 fork process with in-memory rate limits. A second API instance is the condition for bringing Redis back (blueprint appendix), with its own ADR.
- **Migrations use `migrate-mongo`.** Plain ESM files in `apps/api/migrations` (`pnpm --filter @farsh/api db:migrate:create <name>`), applied by `db:migrate` on deploy and recorded in the `changelog` collection, with a 5-minute lock TTL. They stay forward-only: `down` is a no-op and a mistake gets a new migration. No production database ran the old in-repo runner, so its `migrations` collection needs no carrying over. Indexes still come from the Mongoose schemas through `db:indexes`.
- **Web auth follows §9.** `/sign-in` in `(auth)`, account pages under `(dashboard)/dashboard` with `requireSession()` from `lib/auth/dal.ts` in the layout and again in each page. `proxy.ts` sends visitors without cookies to `/sign-in?next=…` and rotates an expired access cookie with `refreshAndContinue`; `/sign-in` itself checks the session on the server instead of in the proxy, so a cookie the API no longer accepts cannot bounce between the two pages. `safeRedirect` guards `next`. `/account` redirects permanently to `/dashboard/profile`. Server calls forward `X-Forwarded-For`, or every visitor would share the web server's rate limit.
- **Forms use react-hook-form + Zod + shadcn Field.** Validation issues from the API land on their fields (`showServerError`), anything else is a sonner toast. The OTP uses `InputOTP` without `pattern`, normalising Persian digits in `onChange` and submitting at six digits. Deleting the account opens an `AlertDialog` before the code is sent. Blank optional text (`optionalText` in contracts) means "not given" on both sides.
- **shadcn components were written by hand** (field, input, textarea, label, spinner, alert-dialog, sonner, tooltip, input-otp) because ui.shadcn.com was unreachable from the build environment. They follow the registry's structure and use the Heritage Loom underlined inputs; they can be diffed against `pnpm dlx shadcn@latest add <name>` later.
- **Providers**: Query (30 s stale, no retry on 4xx), Direction, Tooltip, Toaster and nuqs. No ThemeProvider: 0007 keeps one light theme by the owner's own decision, which outranks the blueprint's dark-mode default. Gallery search and material filter live in the URL (`?q=&filter=`).
- **SmsProvider.send(to, template, args)**, with Melipayamak mapping each template to a pattern. The `business` role exists in contracts; nothing treats it specially yet.
- **Sentry is optional in api and web** (`SENTRY_DSN`, `NEXT_PUBLIC_SENTRY_DSN`). Without a DSN nothing is sent. Request bodies, cookies and headers are never collected, since bodies carry mobiles. The browser reports through `/monitoring`, so the CSP stays `connect-src 'self'`.
- **Tests**: component tests with Testing Library and MSW; Playwright runs the standalone `server.js` (what PM2 runs; `next start` skips the proxy with standalone output) against a small mock API for the server-side calls, in its own CI job. `pnpm audit --prod` runs in CI as a warning.
- **Git**: trunk-based. `develop` is removed; short branches merge into `main` by squash. Renovate keeps dependencies current, waiting 3 days after a release like `minimumReleaseAge`.
